# 经营指标事实接入

新增事实由合同、项目、结算系统各自保存和审核，数析仅采集完整机器快照，在数析自有
`dashboard_metric_snapshot` 表按租户、来源原子发布。不直连源业务库，不在数析登记金额。
投诉本轮暂缓，页面继续明确显示未接入。

## 配置与发布

`METRIC_FACTS_SYNC_ENABLED` 默认 false；显式启用才登记 `contract_metrics`、
`project_metrics`、`finance_metrics` 三个独立同步来源。API与聚合进程共用该开关。
它受 `DASHBOARD_INTEGRATION_SYNC_ENABLED` 总开关控制；关闭后保留快照并标陈旧。
原合同、项目、报告和财务接口及同步来源保持独立，新来源失败不改变原来源成功水位。

迁移 `000037_dashboard_metric_snapshot.sql` 仅新增数析自己的快照表。源接口路径均为
`/internal/v1/dashboard/metrics`，从既有合同、项目、结算机器URL同源推导；复用各自
已登记的最小看板scope及独立身份，不复用secret。拒绝重定向、超过8MiB/10000行、
截断包、错误租户、重复事实、非法金额和未来时间。全部校验成功后才在来源锁事务中
同时发布快照与成功状态；成功水位写入失败会回滚新payload，定时与队列均返回错误。
队列终态不再重复推进该成功水位；许可撤销、租约到期或代次变化拒绝整次发布。
较旧版本不能覆盖较新版本。

发布次序为消费者兼容、业务源迁移/API、平台独立报销候选用途及双端受控配置、最后
启用采集。配置刷新不代替已批准部署流程、备份、迁移、许可与自然运行确认。

## 查询与权限

`GET /api/v1/dashboard/metrics?section=contract|project|report|finance&period=YYYY-MM`
要求对应 `dashboard.<section>.view`。请求不接受租户、组织、团队、人员范围声明；
范围由现有会话验签及在线授权复核提供。ORG/TEAM复用既有组织命名空间守卫，SELF
仅匹配真实归属人员；缺归属行仅租户范围可见。先过滤再统计，不向浏览器返回原始行。

合同默认当前全部普通合同，选月时按原生效月；其余默认北京当前业务月份。返回
`available`、来源更新时间、采集起点、`stale/stale_reason` 与各指标覆盖情况。
未完整发布不等同空业务，来源失败保留旧版本并明确标陈旧。超48小时未成功标陈旧。
页面分别显示新事实采集起点、来源最后更新、快照读取时间，统一北京时间，缺值明确未知。
报告无首次决定月的UNKNOWN/PENDING仍作为当前覆盖数展示，不计首轮终决分母。

## 业务口径

- 折扣按同币种同税基成交额/冻结标准额确定五个精确桶；80%属于八折至九折，
  未知基准另列，不使用当前价格追填旧合同。指定月份仅纳入生效月份精确匹配的合同；
  无生效月份的合同计入`unknown`并在页面标明不归入所选月，全部合同视图仍保留原样本。
- 报告按逻辑主体第一轮有完整证据的终决统计；首次通过/首轮终决为比例，
  待审、历史首次未知、真实退回决定和去重报告分别列示，零分母为null。
- 人员和设备仅使用明确业务日容量及独立确认实际分钟；不从预约、签到或默认8小时
  推算。待审和采集缺口单列，无容量比例为null，售前工时不混入项目实施。
- 确认收入/成本为财务登记及独立复核的不含税额，税额单列；冲回在其确认月为负。
  币种不混加，承担组织、归属人员和项目成本分别汇总，个人成本不等于工资。
- 报销净支出和预付净支出从权威付款/冲正读取，与确认成本分列；项目支出副本不再
  重复采集。旧付款缺审批快照作为`reimbursement_unknown`单列数量，不猜分类。
  已完整验证的合法历史缺口可发布；读取失败或不完整仍整个来源拒绝。

源端新业务需先真实登记并独立审核后才产生已确认指标。空的新确认账本不会把原有
应收自动当收入，也不会把报销付款自动当成本。统计数字不能替代业务凭据。
